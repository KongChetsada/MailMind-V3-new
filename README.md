# MailMind V3

ผู้ช่วยจัดการอีเมลสำหรับคนทำงาน: ดึงอีเมลเข้ามา แยกเป็น 7 ประเภท สรุปใจความ ร่างข้อความตอบกลับ และเสนอรายการที่ลงปฏิทินได้ **ผู้ใช้เป็นผู้ตรวจและกดยืนยันเองทุกครั้ง** ก่อนส่งอีเมลหรือบันทึกลงปฏิทิน

- อีเมลและปฏิทิน: Gmail / Google Workspace + Google Calendar (Microsoft อยู่ในแผนรอบถัดไป)
- AI: เลือกได้ระหว่าง Ollama ในเครื่อง กับ Cloud API (OpenAI, Google Gemini, OpenRouter)
- Frontend: Next.js 16 + React 19 + Tailwind · Backend: Express 5 + Prisma 7 + PostgreSQL

เอกสารออกแบบ แผนภาพ และตาราง "จะแก้อะไร ต้องแก้ที่ไหน" อยู่ใน [docs/DESIGN.md](docs/DESIGN.md)

## สถานะ

| ส่วน | สถานะ |
|---|---|
| ซิงก์ → วิเคราะห์ → ตรวจตาราง → ร่างตอบ → ส่ง / ลงปฏิทิน | เขียนแล้ว ทดสอบกับฐานข้อมูลจริงโดยใช้ตัวเชื่อมจำลอง |
| การวิเคราะห์ด้วย Ollama (`llama3.1:8b`) | ลองกับอีเมลสังเคราะห์ 8 ฉบับแล้ว ยังไม่ได้วัดความถูกต้องกับชุดข้อมูลจริง |
| เชื่อม Gmail / Google Calendar จริง | **ยังไม่ได้ทดสอบ** — ต้องมี Google OAuth credentials |
| Cloud AI (OpenAI, Gemini, OpenRouter) | **ยังไม่ได้ทดสอบ** — ต้องมี API key |
| Microsoft (Outlook / Microsoft 365), IMAP/SMTP | ยังไม่ทำ |
| แก้หรือลบกิจกรรมเดิมเมื่อมีอีเมลขอเลื่อนนัด | ยังไม่ทำ (เสนอเป็นรายการใหม่) |

## เริ่มใช้งาน

ต้องมี Node.js 20+, pnpm, PostgreSQL และ Ollama (ถ้าใช้ AI ในเครื่อง)

```bash
# 1) ฐานข้อมูล
docker compose up -d

# 2) Backend
cd Backend
cp .env.example .env        # แล้วเติมค่าตามหัวข้อถัดไป
pnpm install
pnpm exec prisma migrate deploy
pnpm dev                    # http://localhost:5000

# 3) Frontend (อีกหน้าต่าง)
cd Frontend
cp .env.example .env.local
pnpm install
pnpm dev                    # http://localhost:3000
```

### ค่าใน `Backend/.env`

| ตัวแปร | ความหมาย |
|---|---|
| `DATABASE_URL` | PostgreSQL |
| `JWT_SECRET`, `ENCRYPTION_SECRET` | สตริงสุ่มยาว ๆ คนละค่า เซิร์ฟเวอร์ไม่เริ่มถ้าว่าง — เปลี่ยน `ENCRYPTION_SECRET` แล้ว token และ API key ที่เก็บไว้จะอ่านไม่ได้ ผู้ใช้ต้องเชื่อมบัญชีใหม่ |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` | OAuth client แบบ Web application จาก Google Cloud Console เปิด Gmail API และ Google Calendar API และเพิ่มบัญชีที่จะใช้เป็น Test user |
| `LOCAL_AI_BASE_URL`, `LOCAL_AI_MODEL` | ที่อยู่ของ Ollama และโมเดลเริ่มต้น (`ollama pull llama3.1:8b`) |
| `SYNC_CRON`, `INITIAL_SYNC_DAYS`, `SYNC_MAX_MESSAGES` | รอบซิงก์ จำนวนวันย้อนหลังตอนเชื่อมครั้งแรก และเพดานจำนวนอีเมลต่อรอบ |
| `ANALYZE_CONCURRENCY`, `ANALYZE_MAX_ATTEMPTS` | จำนวนอีเมลที่วิเคราะห์พร้อมกัน และจำนวนครั้งที่ลองใหม่อัตโนมัติ |
| `DEMO_MODE` | `true` = มีปุ่ม "ทดลองด้วยอีเมลตัวอย่าง" ที่หน้าเข้าสู่ระบบ |

### โหมดสาธิต (ไม่ต้องมี Google credentials)

ตั้ง `DEMO_MODE=true` แล้วกดปุ่ม **ทดลองด้วยอีเมลตัวอย่าง** ที่หน้าเข้าสู่ระบบ ระบบจะใช้อีเมลสังเคราะห์ 8 ฉบับจาก `Backend/scripts/samples/emails.json` แทน Gmail เก็บปฏิทินในหน่วยความจำ และ**ไม่ส่งอีเมลจริง** ส่วน AI เป็นของจริงตามที่ตั้งค่า ใช้สำหรับพัฒนาหน้าจอและสาธิตเท่านั้น ห้ามเปิดในระบบที่มีผู้ใช้จริง

## การทดสอบ

```bash
cd Backend
pnpm test                   # ตรรกะหลัก: เวลา ตัวตรวจตาราง ตัวแกะ/ตรวจผลลัพธ์ AI การเข้ารหัส (ไม่ต้องมีฐานข้อมูล)
pnpm test:db                # workflow กับฐานข้อมูลจริง + ตัวเชื่อมจำลอง (ต้อง migrate แล้ว)
node scripts/try-analysis.js --model llama3.1:8b    # ลอง prompt กับโมเดลจริง ดูผลและเวลาต่อฉบับ

cd ../Frontend
pnpm exec tsc --noEmit && pnpm lint && pnpm build
```

`pnpm test:db` ครอบคลุมกรณีที่เคยเป็นปัญหาในรุ่นก่อน: ซิงก์ซ้ำไม่เกิดแถวซ้ำ, ซิงก์พังกลางทางแล้วไม่ข้ามอีเมล, AI ล่มแล้วอีเมลเป็น "วิเคราะห์ไม่สำเร็จ" แทนที่จะถูกจัดเป็นประเภทอื่น, กดส่งซ้ำไม่ส่งซ้ำ, กดยืนยันซ้ำไม่เกิดกิจกรรมซ้ำ, ระยะเวลากิจกรรมตรงกับอีเมล, ปฏิทินล้มเหลวไม่กระทบสถานะการส่ง และผู้ใช้อื่นเข้าถึงข้อมูลไม่ได้

## ข้อจำกัดที่ควรรู้

- **ความเร็วของโมเดลในเครื่อง:** บนเครื่องที่ใช้พัฒนา `llama3.1:8b` ใช้ราว 20–30 วินาทีต่ออีเมลหนึ่งฉบับ อีเมล 100 ฉบับจึงใช้เวลาหลายสิบนาที ระบบวิเคราะห์เบื้องหลังและหน้า Inbox อัปเดตเอง
- **ผลจาก AI อาจผิด:** ประเภท สรุป และวันเวลาเป็นข้อเสนอ ระบบแสดงข้อความอ้างอิงจากอีเมลและติดธงเมื่อยืนยันไม่ได้ แต่ผู้ใช้ต้องตรวจก่อนยืนยัน
- **เมื่อเลือก Cloud AI เนื้อหาอีเมลจะถูกส่งให้ผู้ให้บริการรายนั้น** ระบบไม่สลับผู้ให้บริการเองเมื่อเจ้าที่เลือกล้มเหลว
- **ไม่เก็บเนื้อหาอีเมลเต็มในฐานข้อมูล** เก็บผู้ส่ง หัวข้อ ข้อความย่อ และผลวิเคราะห์ เนื้อหาเต็มดึงจากผู้ให้บริการเมื่อเปิดอ่าน
- **กิจกรรมทั้งวันในปฏิทินไม่นับว่าชน** (ส่วนใหญ่เป็นวันหยุดหรือการแจ้งเตือน)
- **หน้าเว็บแสดงและรับวันเวลาตาม timezone ของเบราว์เซอร์** ส่วนการตรวจเวลาทำงานใช้ timezone ในหน้าตั้งค่า ควรตั้งให้ตรงกัน
- **Google จำกัดสิทธิ์อ่าน Gmail:** แอปที่ยังไม่ผ่านการตรวจของ Google ใช้ได้เฉพาะบัญชีที่เพิ่มเป็น Test user และผู้ดูแล Google Workspace ขององค์กรอาจบล็อกแอปภายนอก
